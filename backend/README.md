# Go Backend

TG账号管理系统 API。需要 Go 1.23+、PostgreSQL 和 Redis。复制仓库根目录 `.env.example` 为 `.env`，填写数据库、Redis、管理员初始化和加密密钥等配置；不要提交 `.env`。本地运行前执行 `set -a; source ./.env; set +a`，再进入 backend 目录执行 `go mod tidy` 和 `go run ./cmd/api`。部署时应通过平台 Secret 或容器 env_file 注入同一组变量。

## 超级管理员初始化
首次启动前设置 SUPER_ADMIN_USERNAME 和至少 16 字节的 SUPER_ADMIN_PASSWORD。数据库中没有超级管理员时，服务会创建一个；已有超级管理员时不会覆盖。初始化后建议从部署环境移除这两个环境变量。

## 认证接口
- POST /api/v1/auth/register：注册租户管理员，创建待激活租户。
- POST /api/v1/auth/login：签发随机 Bearer Token，数据库只保存令牌摘要。
- POST /api/v1/auth/activate：提交一次性卡密。
- GET /api/v1/auth/me：当前用户。
- POST /api/v1/auth/logout：退出当前设备。
- POST /api/v1/auth/password：修改密码并撤销其他设备会话。

## 超级管理员接口
所有接口均要求超级管理员 Bearer Token。
- POST /api/v1/admin/cards：批量生成卡密；请求字段 count、duration_days。明文卡密仅在创建响应中显示一次。
- GET /api/v1/admin/cards?limit=100：查看卡密状态，不返回明文。
- POST /api/v1/admin/cards/{id}/disable：禁用未使用卡密。
- GET /api/v1/admin/tenants?limit=100：查看租户。
- PATCH /api/v1/admin/tenants/{id}/status：设置 active 或 disabled。
- PATCH /api/v1/admin/tenants/{id}/account-limit：设置账号上限。
- PATCH /api/v1/admin/tenants/{id}/expiry：设置租户到期时间，字段 expires_at 使用 RFC3339。

禁用租户后业务请求会被订阅检查拦截。恢复租户不会自动恢复后台任务；后续 Worker 必须保持任务暂停，等待人工确认后恢复。

## 安全边界
Telegram Session 和代理凭据必须加密存储，不得通过普通 API 返回。生产环境必须使用 HTTPS 和密钥管理。业务查询必须从认证上下文取得 tenant_id，不能信任客户端传入。当前仍需补充限流、审计、租户数据访问层和自动化测试，不能直接视为公网生产就绪。

## Telegram 账号 API（基础版）
所有接口使用租户 Bearer Token，并从认证上下文确定租户，不接受客户端指定 tenant_id。
- POST /api/v1/accounts：导入单个账号，字段 phone、display_name、group_name、session、proxy。Session 与代理 JSON 使用 AES-256-GCM 加密后保存；新导入账号状态为 pending，待后续 MTProto Worker 验证连接。
- GET /api/v1/accounts：列出当前租户账号，不返回 Session 或代理密文。
- PATCH /api/v1/accounts/{id}/group：修改账号分组。
- DELETE /api/v1/accounts/{id}：删除当前租户账号。

账号创建时在事务中锁定租户行并检查 account_limit，避免并发请求突破上限。账号读写通过事务级 tenant scope 配合 PostgreSQL RLS。
生产环境必须设置 SESSION_ENCRYPTION_KEY：生成 32 字节随机密钥并以 Base64 或 64 位十六进制字符串配置。密钥应放入密钥管理服务或受保护的部署 Secret，不能提交到仓库。密钥轮换需先实现版本化解密迁移，不能直接替换旧密钥。


## Telegram MTProto

Telegram connectivity is standardized on `github.com/mtgo-labs/mtgo`; device identities are generated by `github.com/mtgo-labs/device-manager` and persisted per account. The current module requires Go 1.26.2 or newer. Configure `TELEGRAM_API_ID` and `TELEGRAM_API_HASH` from my.telegram.org before enabling Telegram login workers. Device model and iOS system version are generated deterministically from the account ID; language defaults can be overridden with environment variables. The API credentials and account sessions must never be exposed to tenant-facing API responses.


## Go verification

GitHub Actions runs `go mod tidy`, `go test ./...`, `go vet ./...`, and builds the API using Go 1.26.2. The workflow is the source of truth for dependency resolution and compilation status.
